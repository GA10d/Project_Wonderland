# 透明素材黑框排查

用户截图中，家具、角色与生成的魔王王座都带有黑色矩形。源 PNG 的透明角落均为 RGBA `(0,0,0,0)`，可见像素的 alpha 正常，素材没有损坏。

macOS Cocoa 原生窗口可以复现，dummy 显示驱动不能复现。原背景使用 `pygame.Surface(...).convert()`，继承窗口的 RGBA 像素格式，alpha mask 为 `0xff000000`，但背景 Surface 没有启用 alpha 合成。贴地板后，实测背景像素从 `(131,109,86,255)` 变为 `(131,109,86,0)`。背景 RGB 仍显示，但随后叠加透明精灵时，透明像素会覆盖这些 alpha=0 的区域，表现为黑色矩形。

修复为明确创建不带 alpha mask 的 32 位 RGB 背景。地板和墙面先合成到不透明背景，再复制到窗口并叠加 RGBA 精灵。无需修改或重新生成素材，也不使用「黑色作为透明色」的方法，因此真正的黑色轮廓保持正常。

原生复验同时发现 macOS 将 1280×900 窗口约束为 1280×843 时，固定高度的预览裁剪会越界。预览现根据实际截图尺寸计算可视区。

验证：

- 普通测试：28 项通过，1 项原生窗口测试按默认配置跳过。
- 启用原生测试：3 项通过，涵盖室内外画面、透明像素/真实黑色区分及受限高度的创作台预览。
- 实际魔王宫殿原生渲染通过，合成后整帧 alpha 均为 255。
